## Grounded packaging compatibility (measured)
- Actual DC57 \`dpkg-deb -f\`: \`Conflicts: ... dev.bechou.le\`; \`Replaces: dev.bechou.le\`. Actual DC57 also owns 9 \`Le*.dylib\` + 9 filters, \`LePrefs.bundle\`, \`usr/share/le/gmaps/fonts\`; therefore cannot coexist with a separate vendor package.
- Independent original vendor 0.2.4 \`deb-scans/le-0.2.4/D_PREFS_GOI.md\` on **main** documents \`Package: dev.bechou.le\`, \`Depends: firmware (>=15.0), firmware (<<27.0), mobilesubstrate, preferenceloader\`, \`Conflicts: org.carwidget.traffic-bubble, org.carwidget.traffic-runtime, com.chou.googlemaps.vietmap\`, \`Replaces: org.carwidget.traffic-bubble, org.carwidget.traffic-runtime\`. There is NO vendor-declared conflict with \`com.chuong.duocar\`. This confirms **package metadata coexistence**, NOT guarantee of future CarPlay runtime.
- Actual LeBubble 0.2.4 signed \`DC57_extracted/.../LeBubble.dylib\` scan (source bytes in container) finds \`CWTrafficBubbleContent\`, \`contentWithSnapshot:\`, \`speedText\`, \`setSpeedText:\`, \`CWTrafficOverlayController\`, \`CWCastBubbleController\`, \`place\`, \`place:\`. These are dynamic optional ABI seams. Original Lề supplies all source rendering, windows, Waze/GOFA/VietMap, route, lanes, limit and snap, no copy in DuoCar. Shim supports separate unpatched original display both \`63\` and \`63 km/h\` by adjusting numeric speed portion only and preserving the original suffix and posted limit.
- **Required installation order when upgrading from DC57:** install \`DC58\` in place of DC57 first (same package identifier, higher Debian version \`1.0.4-hl58\`). Normally dpkg removes vendor files formerly owned by DC57 when upgrading because new manifest no longer contains them. Then install original standalone \`dev.bechou.le_0.2.4_iphoneos-arm64.deb\`, respring/restart CarPlay. Check Sileo installed-package ownership if a package manager differs. The \`/var/mobile\` vendor JSON is user data, NOT in DEB manifest and must not be deleted. The resulting TWO separately owned packages must not share files. If original vendor Le needs iOS 27, it may not install due its own firmware constraint; test vehicle iOS 16 target.
- DuoCar \`Depends\` must NOT hard-require \`dev.bechou.le\`; controls can save DuoCar preferences while vendor is not yet installed, but show no actual traffic bubble until standalone vendor is present. Existing Waze choice stays owned by Le and untouched by DuoCar.
