### Critical HL25 risks identified and patched on the SAME feature branch
1. **HIGH – unverified private scene setter executed on intermediate layout.** Original HL25 `AB25SceneReferenceApply` *called* the two-argument selector when method signature matched. A matching `NSMethodSignature` does not prove semantic ABI, correct receiver, coordinate source or ordering. `ABSceneSettingsApply` runs from `layoutPane:` potentially on intermediate divider sizes, BEFORE `pane.sceneBox` commit: active setter could introduce scene churn/flicker. **FIXED/FAIL CLOSED:** the two- and three-argument selectors are now *read-only capability probes*, return `probe-interface-abi-matches-NOT-CALLED` and `probe-3arg-abi-matches-container-unverified-NOT-CALLED`, no `objc_msgSend` to either in this code slice. Original `setFrame:`, `setInterfaceOrientation:`, foreground/background are not modified. The capability probe is now sampled no more than 1 Hz using a dedicated `dispatch_once`-created lock; do not flood live divider updates. This deliberately means HL25 **does NOT fix reference-size**. The 3-arg container orientation is separately unverified, never guessed.
2. **HIGH – active UIKit hit test in “diagnostic-only” code.** Initial `AB25ProbeKeyboardSurface` called `[keyboard hitTest:edge withEvent:nil]`, which can reach custom view logic and is NOT guaranteed side-effect-free. **REMOVED**. Only `convertRect`, `CGRectIntersection`, class/frame/level/`zPosition`/clip reads remain, sampled by keyboard epoch at up to ~4 Hz (0.25 s interval). `ABNativeKbObserveLayout` now passes the same `UIView *` to the probe instead of recursively looking up LayoutStar twice. The log explicitly marks `keycapRaster=UNKNOWN keycapTouch=UNKNOWN occlusion=UNKNOWN`; when LayoutStar is not found or its projection is invalid, right-edge viewport/clip flags are strings `UNKNOWN`, not false `0`.
3. **MEDIUM – misleading host coordinate conversion.** An initial host `convertRect:toView:box` could be treated as physical clipping even when scene host and box are in separate UIWindows. **FIXED:** add `boxWindowSame`; only convert if `box.window && appView.window && box.window == appView.window`. Otherwise log `UNKNOWN-cross-window`. Log full `NSStringFromCGAffineTransform` rather than treating transform.a as general scale.
4. **MEDIUM – probe-induced main-thread overhead.** Native keyboard subtree lookups, `hitTest`, repeated logs and per-frame method signatures can themselves increase flicker during drag. **MITIGATED** by no hit-test, one LayoutStar scan per observation, ~4 Hz local probe, 1 Hz scene capability probe, host projection only after existing HL24 350 ms stable revision/frame/sceneBox gate. This gate intentionally means *intra-drag transient compositing is BLIND to host projection*; absence of its log during drag cannot prove no event.
5. **OUTSTANDING DIAGNOSTIC LIMIT:** UIWindow levels/zPositions and ancestor projection in hosted-app process cannot by themselves prove pixel-level cross-process compositor order on the physical CarPlay display; even a positive viewport geometric test does not prove keycap hit success. Distinguish H1 local stacking, H2 viewport clipping, H3 keyplane initialization race, H4 remote compositor; no root cause proven.
