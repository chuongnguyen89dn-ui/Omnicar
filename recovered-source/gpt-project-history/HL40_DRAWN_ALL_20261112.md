# HL40 — OmniCar original drawn keyboard, plus native CarPlay extension

**Current requirement (Nguyen, 12 Nov 2026):** BOTH hosted and native CarPlay apps use a drawn keyboard; reuse the **original OmniCar 1.0.3 ABKeyboard UI**. This supersedes the earlier hosted-only acceptance. Do not call it the unmodified original DEB: the native extension is new.

Repo `chuongnguyen89dn-ui/Omnicar`, branch `feature/duocar-hl40-drawn-all-20261112`, base `4c317cfcf73a1c9c8ef762aec457b176c5e15322`. Diagnostic package `1.0.3-hl40drawall1`.

**Hosted:** original `ABKeyboard.m` and `ABTelex.m` compiled again; `ABHostGeometry.m` registers `appbridge.keyboard` and validates `ABHost` pane identity. `ABInApp.m` restores the original empty `inputView`, first-responder state + `appbridge.key` receiver. `ABHostLaunch.m` and disconnect hide the old panel. BridgeWake/kbstate kept. Native UIKit keyboard traits remain compiled but no longer run for hosted drawn mode.

**Native:** `ABNativeDrawnTA.m`, loaded by the existing `com.apple.UIKit` injection filter (directly verified from signed HL37 installer), starts native first-responder clients in Apple native apps and `CarPlayTemplateUIHost`; `CarPlayApp` is both presenter and client for its own text fields. New per-client focus events, `nonce`, ordered `seq` commands, retry and ACK ensure no duplicate characters from retries. The presenter attaches one transparent hit-test-through, non-key `UIWindow` to the active CarPlay scene, then uses the SAME `ABKeyboard`. Clients suppress the system keyboard only on an eligible CarPlay scene and restore only their own temporary inputView; poll at 200ms to recover focus not delivered via standard notifications. No native keyplane or `UIRemoteKeyboardWindow.frame` writes. This follows the observable architecture from the MultiTA binary-analysis document, not copied proprietary code.

**Original UI verification:** exactly four narrow adapters to `ABKeyboard.m` (declarations, host-window resolution, send route and panel-area resolution); independently undoing them reproduces the entire original blob `4eadc1c424a12b5d9de1411c33aa6360bd3985c1`. `ABTelex.m` unchanged at `50e132bd8cda2372ee5a264903cb8c821f2e3991`. Original Zoom default 80%, splitter, Dock/Home, settings, menu, pinch, voice-off retained.

**Actual evidence gates:** `verify_hl40_drawn_all.py` is a source check, not a compiler or vehicle test. No CI/FAT authorized; no automatic runner started. A valid rebuilt and signed arm64 DEB requires Theos, an iPhoneOS SDK and ldid; absent from this session, as confirmed via container filesystem and commands. Use `sh recovered-source/gpt-project-history/build_hl40_arm64_local.sh` only in a checkout on a VM with those tools. The script checks the source, rebuilds all modules, verifies package identity/Mach-O code signature structure and printed SHA. The original HL37/HL39 binary **cannot** be truthfully relabeled as HL40 because it contains neither restored `ABKeyboard` nor the native presenter. No generated valid HL40 DEB or DEVICE PASS yet.

**On-car acceptance:** (1) hosted YouTube/TikTok show original drawn Telex, enter/backspace/hide, no out-of-bounds keyplane; (2) Apple Maps/Music and CarPlayTemplateUIHost native fields show drawn panel, not system keyboard, and type into correct responder; (3) switching native↔hosted/fields, divider resize, close/reconnect, Dock/launcher, settings, pinch unchanged; (4) no duplicate overlays/respring.
